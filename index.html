Servicios

Servicios iniciales

Diseñados para empezar con recursos limitados. La complejidad crece solo cuando exista evidencia.

01

Diagnóstico IA

Mapa de procesos, tareas repetitivas, documentos, tiempos y oportunidades de IA.

02

Alfabetización empresarial

Capacitación práctica para que los trabajadores utilicen IA con criterio y verificación.

03

Pilotos

Soluciones mínimas sobre un proceso real. Se compara el antes y el después.

04

Automatización y agentes

Piloto

PROBLEMA

Informes repetitivos

Hipótesis: parte del tiempo dedicado a recopilar, estructurar y redactar puede reducirse con IA.

MEDICIÓN

Antes / después

Registrar horas, documentos, errores y retrabajo antes de la intervención y repetir después.

DECISIÓN

Continuar / modificar / abandonar

La decisión dependerá de evidencia, no de entusiasmo.

Arquitectura

    
Offline-first: el núcleo (diagnóstico, evidencia, pronóstico) funciona sin Internet usando IndexedDB. Las funciones remotas (API de divisas) se activan solo con conectividad. Los datos nunca salen del dispositivo sin autorización explícita.

    
Botones principales

    
    
      
  • ▶ RUN — Ejecuta una auto-verificación (IndexedDB, canvas, modelo) y genera el último pronóstico.
    • 
      
  • ⇩ Descargar datos — Exporta todos los diagnósticos y evidencias guardados como JSON.
    • 
      
  • ? — Abre y cierra esta ayuda (también se cierra con Esc).
    • 
    

    
Secciones

Ciclo EEGG — paso a paso

    
Cada paso compara su entrada, la acción que ejecutas y la evidencia que produce. Solo se escala lo que se mide.

    

      
1 · Diagnosticar
Mapear el proceso problemático
Entrada: proceso real · Acción: ficha EEGG · Evidencia: tareas repetitivas, tiempos y cuellos de botella

      
↓

      
2 · Priorizar
Elegir UN proceso medible
Entrada: varias oportunidades del paso 1 · Acción: priorizar por frecuencia × tiempo × dolor · Evidencia: objetivo definido y forma de medir acordada

      
↓

      
3 · Aplicar
IA mínima en piloto
Entrada: proceso priorizado · Acción: IA mínima con revisión humana · Evidencia: indicadores antes/después preparados

      
↓

      
4 · Medir
Antes vs después
Entrada: datos del piloto · Acción: registrar evidencia en la app · Evidencia: % real de ahorro medido

      
¿LA EVIDENCIA CUMPLE EL OBJETIVO?

      
SÍ ↓ continúa con Optimizar  ·  NO ⟵ vuelve a 🔁 Aplicar, ajusta y vuelve a medir

      
↓

      
5 · Optimizar
Ajustar con los datos
Entrada: medición del paso 4 · Acción: corregir el flujo según datos · Evidencia: mejora verificable

      
↓

      
6 · Automatizar
Flujo estable + revisión
Entrada: proceso optimizado y estable · Acción: automatizar con humano en el bucle · Evidencia: tiempo liberado medido

      
↓

      
7 · Escalar
Repetir en otro proceso
Entrada: proceso probado y medido · Acción: aplicar el mismo método a otro proceso · Evidencia: repetición con control

      
🔁 Fin del ciclo → siguiente proceso (vuelve a 1 · Diagnosticar)

    

    
Servidor Node.js (opcional)

    
Con node server.js se activa localhost:3000. El endpoint POST /api/forecast usa Prophet real si Python está disponible.

    
Seguridad

    
No guardamos API keys en el frontend. No introduzcas secretos, credenciales ni datos sensibles sin autorización.
